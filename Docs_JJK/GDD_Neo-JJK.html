Neo-JJK Design Specification

Fast, flashy 2D side-scrolling hack-and-slash rogue-lite. Clean codebase, low floor, casual ceiling, and high visual payoff.

Version: 2.0 (Active) Updated: June 2026 Engine: Unity 6 LTS

Purpose & Constraints

This document represents the active design authority for Neo-JJK, replacing the legacy combat guidelines. Neo-JJK has transitioned away from the fighting-game hybrid style to a highly approachable, fast-paced 2D side-scrolling action hack-and-slash rogue-lite.

Production Hard Constraints

The core philosophy governing this design shift is the deliberate elimination of complexity to match development scope:

  • Low development effort as a priority constraint.
  • Casual low skill floor & ceiling — easy onboarding, simple loops.
  • Simple code logic over clever, over-engineered systems.
  • Visual feedback impact (VFX) over animation frame-perfection.

Platform and Input Philosophy

PC Keyboard & Mouse controls represent the authoritative design layout. Controllers translate these exact verbs without precision variation.

Key Bind Combat Verb Behavior & Gameplay Logic
A / D Move Left / Right Locomotion. Holding left/right influences dash direction.
Space Jump / Double Jump Vertical navigation. Double jump available for all characters.
LMB Basic Attack (BA) State-based simple linear attack chain (2-3 strikes).
RMB Skill Triggers character skill. Interrupts BA. Cooldown-gated.
Shift Dash Invincibility-frame dash. Responsive interrupt verb.
Q Ultimate Glow/Slow-mo visual finisher. Interrupts active skills.
1 / 2 / 3 Team Swap Swap active character. Toggles team slot. Inherits buffer.

Authoritative Input Rules

  • 12-Frame Input Buffer: Inputs pressed within 12 frames prior to current action recovery are cached and executed instantly.
  • Input Type Priority: Hierarchical evaluation: System/Swap/Dodge > Skill/Ultimate > Jump > Basic Attack > Locomotion. Higher priority overrides current buffer.
  • Team Swap Cancel: Swapping clones the incoming character into the field with a quick swap attack sequence, while the outgoing character finishes their active state before disappearing.

Simplifying the player's core cycle allows them to focus on immediate combat enjoyment and upgrades.

Genshin-Style Team Rotation Flow

Optimal combat output revolves around cycling characters to keep buffs active, rather than manual execution:

1. Main DPS Active

Stays on field. Delivers basic chains and counts cooldowns.

2. Swap Support/Buff

Quick-swap in to place shields, apply elemental states, or summon helpers.

3. Swap Main DPS & Burst

Swap back to Main DPS, inheriting active buffs to burst down enemies.

Fast room clearing: group targets, cycle roles, deploy ultimate bursts, collect upgrades.

Combat Direction

Rotation-based structure replaces legacy combo-routing. The active design focuses on clear roles and simplified reactions.

Kept Systems
  • Simple Stagger / Knockback: Basic hit animations.
  • Dodge / Dash: Invulnerable frames for survival.
  • Team Swap Cancel: Old char finishes action before disappearing.
  • Buffer Inheritance: Key strings execute smoothly.
  • Hit-Stop: Immediate combat feedback freeze.
Role Budget
  • Main DPS: High field time, sustained normal chains.
  • Sub DPS: Cooldown dump, instant swaps.
  • Support: Shields, heals, party-wide damage amplification.
Deprecated Mechanics

To lower development burden, these fighting-game systems are completely disabled:

  • Branching combo trees & timing windows.
  • 60fps frame advantage & precision rules.
  • Real airborne juggle physics & gravity chains.
  • ZZZ-style perfect parry-swap triggers.
  • Stance micro-loops & directional inputs.
Hit reactions

Only aesthetic hit reaction exists. Launch/juggle physics are animated tricks, not state rules.

  • No stagger-lock loops.
  • No combo requirement counters for scoring/scaling.

Enemy Archetypes

Trash Enemy

Low HP. Staggers on normal hit. Basic target used for fast room clear feel.

Ranged Enemy

Forces repositioning. Fires telegraph-traced arrows/bullets from backline.

Guard / Shield Enemy

Blocks frontal strikes. Weak from behind. No parry check needed.

Elite Mini-Boss

Super-armor status on heavy swings. Displays ground danger warning decals.

Boss Battle Direction

Boss battles mimic generic 2D action stages (Hollow Knight style) over fighting-game dynamic AI. Large visual sweeps and predictable recovery loops are key.

Standard Boss Rules

  • Large body size with strong silhouette readability.
  • Super armor ignores active staggers during move wind-up.
  • Telegraphed projectile bullet patterns.
  • Phase shifts (adds ranged elements at 60% HP, speeds up at 30%).
  • Clear recover windows (Boss freezes for 1.5s after large attacks).

Legacy Boss Behaviors (Removed)

  • No launcher juggles or physics-driven air combos.
  • No infinite stagger loops.
  • No frame-trap checks or input-reading block behaviors.
  • No complex close-quarter collision checks.
The Punish Window Cycle
Boss Winds Up (Warning Box) Player Dashes Through / Moves Boss Strike Misses Boss Enters Recovery Stun (1.5s) Player Swaps & Bursts!

Project Stack & Architecture

The code architecture is designed to prevent technical debt. Data-driven ScriptableObjects organize content, and simple FSM structures control runtime logic.

Subsystem / Tool Stack Value Active Architecture Role
Unity Engine Unity 6 LTS (6000.x) Authoritative Runtime Engine.
Render Pipeline URP 17.x Rendering, Post-processing volume effects, shader graphics.
Input System Input System 1.8.x `PlayerInput` handles keyboard mapping and buffer windows.
Camera Manager Cinemachine 3.x Combines combat-room camera clamping and screenshake triggers.
AI Behavior Graph Unity Behavior Graph Controls enemy chase, patrol, and attack FSM states.

Subsystem Codebase Scale
